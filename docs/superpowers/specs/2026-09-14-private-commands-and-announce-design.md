# nonebot-plugin-xianmei v2 变更设计：私聊群控 + 出现播报

日期：2026-09-14
状态：已确认
基线：v1（2026-09-11 合并于 main，2562dfa）

## 1. 目标

1. superuser 可通过**私聊**机器人管理**任意群**的献媚配置
2. 群主（桃神）出现触发献媚时，先播报「检测到 XX 出现」「开始献媚」，再发彩虹屁
3. （确认项，无改动）每日上限本就可通过 `/献媚设置上限` 调整，v2 将其纳入私聊控制

## 2. 私聊命令（commands.py）

- 群聊发送：行为不变，作用于当前群（群号参数省略）
- 私聊发送：第一个参数必须为**群号**，其后为原参数：
  - `/献媚设置群主 <群号> <QQ号>`
  - `/献媚设置上限 <群号> <N>`
  - `/献媚设置冷却 <群号> <分钟>`
  - `/献媚开关 <群号>`
  - `/献媚状态 <群号>`
  - `/献媚预览 <群号>`
- 私聊缺群号或群号非法（非数字）→ 回复用法提示（含正确示例）
- 权限不变：全部仅 superuser；群号只用于定位配置，不做"机器人是否在群内"的校验（YAGNI）

### 参数解析规则

每个命令统一走一个解析辅助：`resolve_group_and_arg(event, plain_text) -> tuple[str | None, str]`：
- 群聊消息 → (str(event.group_id), plain_text)
- 私聊消息 → 第一个 token 为群号；取不到/非数字 → 用法提示并终止；剩余 token 为命令参数

## 3. 出现播报（__init__.py handler）

- decide() 返回 True 时，依次发送三条独立消息：
  1. `🔔 检测到 {name} 出现！`
  2. `🫡 开始献媚！`
  3. 彩虹屁本体（原逻辑）
- `{name}` 取消息发送者的群名片（sender.card），为空回退 QQ 昵称（sender.nickname），再回退 `桃神`
- 播报不计入每日上限；日额度用尽时 decide() 为 False，不播报也不发（保持静默）
- 冷却逻辑不变：冷却窗口内 decide() 为 False，无播报

## 4. 测试

- `resolve_group_and_arg` 单测：群聊直通；私聊带群号；私聊缺群号/非法群号
- 命令集成：私聊 `/献媚设置群主 123456 6867955`（superuser）→ 目标群配置生效；私聊非 superuser 被拒
- 播报集成：群主消息触发 → 断言三条消息按顺序发送（检测到→开始献媚→彩虹屁）
- 现有 38 个测试保持绿色（群聊用法不变）
